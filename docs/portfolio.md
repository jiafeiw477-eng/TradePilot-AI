# TradePilot AI 项目作品集说明

> 本文区分“当前代码事实”“本次实际测试结果”和“未来设想”。未进行的真实 API、真实客户或浏览器测试不会被描述为已验证成果。

## 1. 项目概览

**TradePilot AI** 是一个面向外贸询盘处理流程的本地 Streamlit 原型。当前核心路径为：业务员提交英文邮件，使用 DeepSeek 获取结构化分析和英文回复草稿，将成功结果保存到本机 SQLite，并维护后续跟进状态。

本项目适合作为 AI 产品/运营实习作品集中的一个原型案例，展示需求拆解、AI 能力边界、错误场景设计、本地数据持久化和基础自动化测试。它不是已上线产品，也没有用户量、准确率、商业收益或节省时间的实测结论。

## 2. 产品背景与用户痛点

### 背景

外贸业务沟通通常以邮件或消息中的非结构化文字开始。业务员需要理解客户表达，并将关键信息整理成后续可执行的业务动作。

### 需要解决的问题

- 英文邮件中的产品、数量、价格、交货时间等信息需要人工逐项整理。
- 未提及的信息容易在转述或回复时被误当作已确认事实。
- 回复草稿和跟进备注可能散落在邮件、文档或个人记录中。
- 询盘分析与后续跟进状态之间缺少一个简单的连续操作流程。

这些是本原型的产品问题假设；尚未通过访谈、行为数据或客户研究验证其普遍性和严重程度。

## 3. 目标用户与核心使用流程

### 目标用户

- 初步处理英文询盘的外贸业务员或业务助理。
- 希望快速整理邮件信息，但仍会复核 AI 输出的中小型出口团队成员。

### 当前原型流程

1. 用户打开“询盘助手”，粘贴英文邮件或编辑页面预填示例。
2. 用户点击“AI 分析”。页面会提示邮件将发送到 DeepSeek，调用可能产生费用。
3. 服务层检查配置和输入，并调用 DeepSeek Chat Completions；收到有效结构化响应后展示翻译、需求、辅助意向判断、风险、英文回复和跟进建议。
4. 成功结果写入 SQLite；请求失败或分析格式无效时，不创建成功历史记录。
5. 用户可在“历史记录”查看完整结果、复制英文回复，或在删除前勾选确认。
6. 用户在“询盘管理”按关键词、状态或业务优先级筛选，并维护跟进状态、业务优先级、备注和下次跟进日期。管理字段保存在 SQLite。

## 4. 功能需求与设计理由

| 需求 | 当前实现 | 设计理由与边界 |
|---|---|---|
| 展示英文询盘的结构化分析 | DeepSeek 返回 JSON；服务层校验关键字段 | 便于页面分区展示；真实输出仍需人工核实 |
| 缺失内容不猜测 | Prompt 要求未提及内容填写“未提供” | 避免将未确认的价格、库存、认证、交期当成事实 |
| 显式区分 AI 请求状态 | 用户主动提交；配置、HTTP、超时、连接和解析错误有不同提示 | 失败时不使用假结果，不默认重试 |
| 保存成功分析 | SQLite 本地存储分析和询盘内容 | 允许刷新或重启后继续查看；保存失败会提示 |
| 维护后续跟进 | 业务状态、业务优先级、备注和日期自动保存到 SQLite | 让分析结果与后续动作关联；业务优先级不由 AI 意向自动决定 |
| 保护本地凭据 | 从 `.env` 读取；忽略 `.env` 和数据库目录 | 避免凭据写入代码和将本地数据库误提交 |
| 提供可复制回复 | 使用 Streamlit 原生代码区复制控件 | 不增加前端脚本或依赖；剪贴板行为受浏览器权限影响 |
| 支持可重复测试 | 数据库测试传入临时文件路径，API 分析使用模拟客户端 | 测试无需改动用户数据库，也不产生真实 API 费用 |

### 当前明确不在范围内

产品 CSV/Excel 导入和目录匹配、CRM 联系人资料、多用户权限、云端部署、分析准确率基准、数据脱敏流水线、生产级备份/恢复均未实现。

## 6. 项目架构

```text
app.py
  ├── Streamlit 页面与用户交互
  ├── services.inquiry_ai
  │     └── services.deepseek_client
  └── services.inquiry_history
        └── data/inquiry_history.sqlite3

inquiry_parser.py
  └── 独立的规则解析逻辑（当前不作为询盘助手页面主分析路径）

tests/
  ├── 测试 Streamlit 页面交互
  ├── 使用模拟对象测试 AI 响应和错误处理
  └── 使用 pytest 临时目录测试 SQLite
```

主要文件：

- `app.py`：入口、导航、表单、结果展示、历史记录和询盘管理界面。
- `services/deepseek_client.py`：使用 `python-dotenv` 加载配置并创建 OpenAI 兼容客户端。
- `services/inquiry_ai.py`：提示词、真实请求、超时与错误处理、JSON 结构验证。
- `services/inquiry_history.py`：SQLite schema 初始化/迁移、记录增删查、跟进字段更新、筛选和统计。
- `inquiry_parser.py`：本地规则式解析逻辑，独立于当前 AI 页面调用流程。

依赖清单包含 Python、Streamlit、Pandas、python-dotenv、OpenAI SDK 和 pytest。当前应用源代码未直接导入 Pandas。

## 8. 安全与数据注意事项

- API Key 只应该保存在本地 `.env` 或安全的环境变量中；不要放在截图、作品集、代码或对话里。
- `.env.example` 的 Key 字段为空，是占位模板，不包含真实密钥。
- `.gitignore` 忽略 `.env`、`.env.*`（保留 `.env.example`）、`data/`、`.venv/` 和缓存文件。
- 历史记录含客户邮件及 AI 输出，SQLite 当前为未加密本地文件。作品集截图请使用合成或脱敏内容。
- `scripts/test_deepseek_connection.py` 会真实调用 API，可能计费；自动化测试不应调用它。

1. **验证用户问题**：访谈外贸业务员，厘清最费时步骤、信息字段和现有跟进工具。

4. **开发产品目录**：支持 CSV/Excel 导入、字段映射、数据校验和匹配理由。
5. **扩展 CRM**：维护客户联系人及独立跟进活动，考虑导出、备份和访问控制。
6. **提升隐私与可靠性**：评估敏感信息脱敏、数据库保护、错误监控、浏览器自动化和恢复策略。
7. **定义业务指标**：先建立基线和测量方法，再考虑任务完成时间、人工采纳率等指标，不预先承诺提升幅度。
