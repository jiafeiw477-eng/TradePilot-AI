# TradePilot AI 项目作品集说明

> 本文区分“当前代码事实”“本次实际测试结果”和“未来设想”。未进行的真实 API、真实客户或浏览器测试不会被描述为已验证成果。

## 1. 项目概览

**TradePilot AI** 是一个面向外贸询盘流程的 Streamlit 工作台原型。业务员可以提交英文邮件，使用 DeepSeek 获取结构化分析和英文回复草稿，将成功结果保存到 SQLite，并在产品目录、客户管理、分析面板与多轮 AI 助手中继续处理业务信息。

本项目适合作为 AI 产品/运营实习作品集中的一个原型案例，展示需求拆解、AI 能力边界、错误场景设计、本地数据持久化和基础自动化测试。它不是已上线产品，也没有用户量、准确率、商业收益或节省时间的实测结论。

## 2. 产品背景与用户痛点

### 背景

外贸业务沟通通常以邮件或消息中的非结构化文字开始。业务员需要理解客户表达，并将关键信息整理成后续可执行的业务动作。

### 需要解决的问题

- 英文邮件中的产品、数量、价格、交货时间等信息需要人工逐项整理。
- 未提及的信息容易在转述或回复时被误当作已确认事实。
- 回复草稿和跟进备注可能散落在邮件、文档或个人记录中。
- 询盘分析与后续跟进状态之间缺少一个简单的连续操作流程。

这些是本原型的产品问题假设；尚未通过访谈、行为数据或客户研究验证其普遍性和严重程度。

## 3. 目标用户与核心使用流程

### 目标用户

- 初步处理英文询盘的外贸业务员或业务助理。
- 希望快速整理邮件信息，但仍会复核 AI 输出的中小型出口团队成员。

### 当前原型流程

1. 用户打开“询盘助手”，粘贴英文邮件或编辑页面预填示例。
2. 用户点击“AI 分析”。页面会提示邮件将发送到 DeepSeek，调用可能产生费用。
3. 服务层检查配置和输入，并调用 DeepSeek Chat Completions；收到有效结构化响应后展示翻译、需求、辅助意向判断、风险、英文回复和跟进建议。
4. 成功结果写入 SQLite；请求失败或分析格式无效时，不创建成功历史记录。
5. 用户可在“历史记录”查看完整结果、复制英文回复，或在删除前勾选确认。
6. 用户在“询盘管理”按关键词、状态或业务优先级筛选，并维护跟进状态、业务优先级、备注和下次跟进日期。管理字段保存在 SQLite。
7. 用户在产品目录维护真实产品资料，在客户管理维护客户并关联已有询盘；AI 助手按需查询匹配记录，生成的回答不等同于邮件已发送。
8. 业务概览基于 SQLite 中真实询盘进行统计、趋势、筛选和 CSV 导出。

## 4. 功能需求与设计理由

| 需求 | 当前实现 | 设计理由与边界 |
|---|---|---|
| 展示英文询盘的结构化分析 | DeepSeek 返回 JSON；服务层校验关键字段 | 便于页面分区展示；真实输出仍需人工核实 |
| 缺失内容不猜测 | Prompt 要求未提及内容填写“未提供” | 避免将未确认的价格、库存、认证、交期当成事实 |
| 显式区分 AI 请求状态 | 用户主动提交；配置、HTTP、超时、连接和解析错误有不同提示 | 失败时不使用假结果，不默认重试 |
| 保存成功分析 | SQLite 本地存储分析和询盘内容 | 允许刷新或重启后继续查看；保存失败会提示 |
| 维护后续跟进 | 业务状态、业务优先级、备注和日期自动保存到 SQLite | 让分析结果与后续动作关联；业务优先级不由 AI 意向自动决定 |
| 保护本地凭据 | 从 `.env` 读取；忽略 `.env` 和数据库目录 | 避免凭据写入代码和将本地数据库误提交 |
| 云端配置凭据 | 支持从 Streamlit Secrets 读取 DeepSeek 配置 | 云端无需将密钥写入代码或仓库；未配置时仍可启动并显示提示 |
| 提供可复制回复 | 使用 Streamlit 原生代码区复制控件 | 不增加前端脚本或依赖；剪贴板行为受浏览器权限影响 |
| 维护产品目录 | 产品 CRUD、SKU/价格/MOQ 校验和关键词检索均写入 SQLite | 让 AI 助手可以依据数据库中的实际产品字段回答 |
| 维护客户资料 | 客户 CRUD、重复检测、归档、详情与询盘关联写入 SQLite | 避免删除有关联询盘的客户时连带删除历史 |
| 业务数据分析 | 查询真实记录的统计、趋势、状态/产品/地区分布及筛选导出 | 不使用随机或硬编码业务指标；草稿数不当作已回复数 |
| AI 多轮助手 | 复用 DeepSeek 客户端、限制历史消息并按需检索有限业务上下文 | 减少不必要的数据发送；遇到业务数据读取异常时取消请求 |
| 持久化偏好 | 将回复语言、语气、长度与通用选项保存到 SQLite | 设置真正影响后续 AI 助手提示词与分析默认范围 |
| 支持可重复测试 | 数据库测试传入临时文件路径，API 分析使用模拟客户端 | 测试无需改动用户数据库，也不产生真实 API 费用 |

### 当前明确不在范围内

产品 CSV/Excel 导入、客户资料批量导入、多用户登录/权限/数据隔离、分析准确率基准、自动脱敏流水线、生产级备份/恢复均未实现。虽然支持 Streamlit Community Cloud 配置，但尚未完成真实云端部署验证。

## 5. 当前版本功能清单

### 已实现

- Streamlit 中文导航和询盘分析页面。
- DeepSeek 实际请求代码路径、结构化结果校验、API 错误分类。
- 仅成功分析后保存的 SQLite 历史记录；支持展开查看和删除确认。
- 英文回复代码区及原生复制控件。
- 询盘管理统计、关键词搜索、状态/优先级筛选和持久化编辑。
- SQLite 旧表增量迁移，为旧记录设置合理默认跟进状态和优先级。
- 真实业务数据分析，包括日期/状态筛选、趋势、状态/产品/国家分布、规则型洞察和 CSV 导出。
- 产品目录 SQLite CRUD、SKU 唯一校验、价格/MOQ 校验、搜索/筛选、详情和确认删除。
- 客户 SQLite CRUD、邮箱校验、重复提醒、归档/恢复、关联询盘及历史保护。
- 多轮 AI 助手、任务快捷入口、按需业务上下文、回复偏好注入和失败时保留输入。
- 非敏感应用偏好设置、模型配置状态、显式点击才触发的连接测试和系统状态。
- 独立规则解析模块及对应测试。
- `.env.example` 占位配置和 `.gitignore` 凭据/数据忽略规则。

### 部分实现或未验证

- **DeepSeek 实际服务可用性**：代码路径存在，测试通过模拟客户端；本文编写期间没有真实 API 调用，因而不确认 API Key、账户额度和服务状态。
- **复制功能**：已确认 Streamlit 代码区在页面中显示正确文本；没有真实浏览器剪贴板测试。
- **规则解析器**：代码及单元测试存在，但当前询盘助手页面调用的是 DeepSeek 服务，不是规则解析器。
- **数据安全**：`.env`、`.streamlit/secrets.toml` 和数据库目录都有忽略规则；SQLite 数据文件本身未加密。Streamlit Community Cloud 本地文件系统不保证持久化，应用重启或重新部署后数据可能丢失。
- **云端访问控制**：当前没有用户登录或数据隔离。公开部署时，访问者可能触发消耗 DeepSeek 额度的请求，也可能访问同一应用共享的数据；不要把未受控的云端原型用于真实客户资料。
- **Git 历史中的个人信息**：此前首次提交元数据带有作者邮箱，旧版 README 曾包含本机目录。最新 README 已改为相对/通用路径，但普通提交不会清除旧历史。
- **产品导入**：尚未实现 CSV/Excel 导入和导入字段映射。
- **系统边界**：没有用户登录、角色权限、记录级隔离和备份恢复；云端 SQLite 不保证持久化。

## 6. 项目架构

```text
app.py
  ├── Streamlit 页面与用户交互
  ├── services.inquiry_ai ── services.deepseek_client
  ├── services.ai_assistant ── services.product_catalog
  │                         ├─ services.customer_manager
  │                         ├─ services.app_settings
  │                         └─ services.inquiry_history
  └── services.database ── SQLite（data/inquiry_history.sqlite3）

inquiry_parser.py
  └── 独立的规则解析逻辑（当前不作为询盘助手页面主分析路径）

tests/
  ├── 测试 Streamlit 页面交互
  ├── 使用模拟对象测试 AI 响应和错误处理
  └── 使用 pytest 临时目录测试 SQLite
```

主要文件：

- `app.py`：入口、导航、表单、结果展示、历史记录和询盘管理界面。
- `services/deepseek_client.py`：从环境变量、`.env` 或 Streamlit Secrets 加载配置并创建 OpenAI 兼容客户端。
- `services/inquiry_ai.py`：提示词、真实请求、超时与错误处理、JSON 结构验证。
- `services/inquiry_history.py`：SQLite schema 初始化/迁移、记录增删查、跟进字段更新、筛选和统计。
- `services/database.py`：共享 SQLite 数据库路径、连接和受限表名查询。
- `services/product_catalog.py`：产品校验、增删改查、分类/状态筛选及 AI 查询匹配。
- `services/customer_manager.py`：客户资料校验、查重、归档/恢复和询盘关联支持。
- `services/app_settings.py`：非敏感偏好校验、持久化和提示词构造。
- `services/ai_assistant.py`：复用 DeepSeek 客户端进行多轮对话，按需检索有限产品、客户和询盘上下文。
- `inquiry_parser.py`：本地规则式解析逻辑，独立于当前 AI 页面调用流程。

运行依赖由 `requirements.txt` 管理（Python、Streamlit、Pandas、python-dotenv 和 OpenAI SDK）；`requirements-dev.txt` 在运行依赖上增加 pytest。部署入口为 `app.py`。

## 8. 安全与数据注意事项

- API Key 只应该保存在本地 `.env` 或安全的环境变量中；不要放在截图、作品集、代码或对话里。
- `.env.example` 的 Key 字段为空，是占位模板，不包含真实密钥。
- `.gitignore` 忽略 `.env`、`.env.*`（保留 `.env.example`）、`.streamlit/secrets.toml`、`data/`、`.venv/` 和缓存文件。
- 历史记录含客户邮件及 AI 输出，SQLite 当前为未加密本地文件。作品集截图请使用合成或脱敏内容。
- Streamlit Community Cloud 上的 SQLite 文件仅适合临时原型验证，不能作为云端永久数据存储；需要持久化时应改用托管数据库并增加访问控制。
- `scripts/test_deepseek_connection.py` 会真实调用 API，可能计费；自动化测试不应调用它。
